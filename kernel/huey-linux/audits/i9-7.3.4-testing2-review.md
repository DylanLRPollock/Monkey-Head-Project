## Explicit non-blocking Kconfig decisions for first offline build

1. **Binder:** `CONFIG_ANDROID_BINDER_IPC=n` (upstream bool, not
   the original Debian-patched tristate module); Waydroid is **not**
   supported or qualified on this first candidate. Do not insert
   speculative kernel patches into the authenticated 7.3.4 source.
   If needed, evaluate a future candidate with `=y` and
   `CONFIG_ANDROID_BINDERFS=y` based on actual runtime requirements.
2. **Module signing:** `CONFIG_MODULE_SIG=y`,
   `CONFIG_MODULE_SIG_ALL=y`,
   `CONFIG_MODULE_SIG_KEY="certs/signing_key.pem"`,
   `CONFIG_MODULE_SIG_FORCE=n`.
   Retain as observed for the first *private* test build. Kernel kbuild
   may generate a private key/cert in the isolated output tree.
   Never commit or publish `*.pem`, release those files through CI,
   or assume that this key is enrolled in Secure Boot. Secure Boot is
   disabled on the known host; re-evaluate before booting elsewhere.
3. **Rust abstractions:** Core `CONFIG_RUST=y` restored, but
   `CONFIG_RUST_FW_LOADER_ABSTRACTIONS=n` and
   `CONFIG_RUST_PHYLIB_ABSTRACTIONS=n` differ from Debian's `y`
   baseline. Their absence does not block HueyOS's current Optane,
   GPU or inference functionality. Restore in a future candidate only
   if Rust driver integrations depend on them.
4. Some Debian-only or upstream-removed Kconfig symbols disappear;
   this is **not** direct proof of removed runtime functionality.
   `CONFIG_DRM_PANIC_SCREEN_QR_CODE=n` is a minor feature regression;
   none is the critical Optane root RAID10 or V100 path.
