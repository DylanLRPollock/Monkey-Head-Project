## Review before compilation — explicit changes and regressions

1. **Rust dropped out of the candidate unexpectedly.**
   Debian baseline: `CONFIG_RUST=y`; upstream candidate:
   `CONFIG_RUST=n` / Rust compiler & LLVM version Kconfig probes
   resolved to `0`. More Rust-specific symbols were removed because
   the parent feature was unavailable. Most likely a toolchain/dependency
   issue, **now confirmed for the first blocking prerequisite** by
   `make rustavailable`: `Rust compiler 'rustc' could not be found`.
   Install Forky's `rustc rust-src bindgen rustfmt rust-clippy` via APT,
   with `libclang-dev` pulled in as a bindgen dependency. Re-run
   `rustavailable` to uncover any further missing prerequisites.
   Do not assume Rust support is restored until all checks pass.
   If restored, **regenerate a separate immutable testing2 candidate**
   rather than silently modifying the fingerprinted testing1 config.
2. **Android Binder no longer builds as the previously loaded module.**
   Debian baseline: `CONFIG_ANDROID_BINDER_IPC=m`.
   Upstream `olddefconfig` emitted
   `warning: symbol value 'm' invalid for ANDROID_BINDER_IPC`;
   resulting option is `CONFIG_ANDROID_BINDER_IPC=n`. Debian carries a
   source patch allowing Binder as a module, whereas upstream offers
   different configuration semantics. Decide whether Waydroid/Android
   compatibility needs preserving; investigate Debian patch applicability
   to 7.3.4 before carrying a patch. Do not claim that `m` is valid in
   the unpatched tree.
3. **Automatic module signing newly enabled by defaults**:
   `CONFIG_MODULE_SIG_ALL=y` and signing key
   `CONFIG_MODULE_SIG_KEY="certs/signing_key.pem"`.
   On a default build kernel tooling may generate a private key
   *in its output tree*. Assess packaging/secret handling; preserve
   `CONFIG_MODULE_SIG=y` signing capability, keep private keys out of
   git/CI/public release, choose whether automatic signing belongs
   in the first testing profile. Secure Boot is disabled on this host,
   but the external proprietary module still needs exact target headers.
4. **Other changed symbols**: `CONFIG_CRYPTO_AEAD=m -> y`,
   `CONFIG_BLK_INLINE_ENCRYPTION=n -> y`,
   `CONFIG_SND_SOC_TAS2783_SDW=n -> m`,
   `CONFIG_CC_VERSION_TEXT` wrapper changes, and
   `CONFIG_RUSTC_LLVM_MAJOR_VERSION`, `CONFIG_RUSTC_LLVM_VERSION`,
   `CONFIG_RUSTC_VERSION` become `0`.
   Review the ASOC audio module drift without assuming a regression.
5. **Removed and renamed Kconfig symbols** include previously
   Debian-specific Binder/Nouveau entries and current upstream code
   reorganization. A removed symbol is not automatically equivalent
   to loss of its functionality; assess actual driver/config behavior.
6. `olddefconfig` emitted precisely one visible warning about Binder;
   otherwise completed. No `vmlinux` or NVIDIA `.ko` has been built
   for 7.3.4; no install, boot or stress test has occurred.
