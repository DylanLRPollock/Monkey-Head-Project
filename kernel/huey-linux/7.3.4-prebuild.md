# HueyOS Linux 7.3.4 — pre-build specification

**Status:** approved design, **not** hardware-qualified or installable.
**Host:** Debian Forky, Intel Core i9-12900K, ASUS TUF Z790-PLUS WIFI.
**Development branch:** `feature/huey-kernel-7.3.4`.
**Initial KERNELRELEASE:** `7.3.4-huey-testing1`.
**Target qualified KERNELRELEASE:** `7.3.4-huey-stable`.

## Release state machine

1. `testingN` is the immutable candidate identity. Never overwrite a previous
   tested kernel/module/headers bundle; increment N for config/source/patch changes.
2. The release manifest records upstream source hash, signed source provenance,
   precise .config hash, config delta, compiler/binutils versions, patch hashes,
   build environment, NVIDIA vendor-source reference (no vendor files), module
   hashes, signing verification, machine qualification, and rollback reference.
3. The builder must require **exact** `KERNELRELEASE` equality *before* `bindeb-pkg`.
   A missing, duplicate, SCM, unexpected distro or version suffix is an error.
4. `stable` is a distinct release identity, not an on-disk rename. Rebuild
   kernel, matching headers, NVIDIA modules, initramfs and signature artifacts
   with `-huey-stable`; repeat release-verification gates, relevant runtime
   regression tests and checksums before promotion.
5. Stable promotion is by explicit operator approval. No installer/reboot or
   MOK-enrollment action is part of CI or the Python build CLI.

## Build environment

* Maintain **Forky** on the host. Do not mix Trixie or Sid repositories into
  the host to satisfy build requirements.
* Use official upstream Linux 7.3.4 tarball. `source.lock.json` stays
  `unresolved` until the archive checksum is verified against kernel.org's
  signed checksum file or detached signature and manually pinned.
* Build Debian-compatible `.deb` image/headers with a pinned, tested compiler
  and binutils. Prefer `-j4` initially on 16 GiB RAM and monitor temperature,
  free space and CPU/memory pressure.
* Use the Debian running config as a starting point, run `olddefconfig` against
  7.3.4, review the *full* config delta before compiling. Do not blindly
  use `localmodconfig` to discard unused recovery/storage drivers.
* Set `CONFIG_LOCALVERSION=""` and disable `CONFIG_LOCALVERSION_AUTO`.
  Supply the only suffix through the builder's `LOCALVERSION` argument.
  Explicitly verify that there are no unwanted `localversion*` files.
* Verify UEFI/shim/GRUB, Secure Boot, module trust, root filesystem, initramfs
  and fallback boot entry before considering a test boot.

## V100 compatibility contract

* V100/Volta is `sm_70`. NVIDIA **proprietary** `580.196.07` is the known
  workstation baseline. NVIDIA's open kernel modules are not compatible with
  Volta. Nouveau is not a CUDA-compatible replacement for this workload.
* The R580 source/installer and built proprietary `.ko` modules stay local and
  are **not** committed, uploaded to public GitHub CI, or included in public
  release artifacts. The operator supplies a verified local vendor/DKMS tree.
* HueyOS may ship original integration software, build/verification scripts,
  hardware inventory, V100 capability detection, policy, manifests, test
  harnesses, and independently reviewed patch metadata. It does not reverse
  engineer the closed driver, bypass GPL-only kernel interfaces, or claim to
  relicense proprietary binaries.
* Build `nvidia` and `nvidia-uvm` against exact target headers and full
  `Module.symvers`. Check `vermagic`, driver version, symbols, module flavor,
  secure-boot signature and initramfs inclusion. Never silently patch or
  execute vendor installers on the live machine.
* CUDA **12.9** is the last toolkit family that supports compiling for V100
  `sm_70`. Newer toolkits may run older compatible binaries through the driver
  but CUDA 13 no longer compiles native V100 code. Do **not** override its
  unsupported-target check and assume functionality.
* Select **GCC/G++ 14** for CUDA 12.9 builds (within NVIDIA's supported GCC
  6–14 range); keep Forky's global compiler unchanged. Record and validate a
  separate kernel-toolchain compiler as necessary.
* For own CUDA projects, prefer explicit `sm_70` targets such as
  `-gencode arch=compute_70,code=sm_70`,
  `CMAKE_CUDA_ARCHITECTURES=70`, or `TORCH_CUDA_ARCH_LIST=7.0`.
  These flags do not make closed CUDA 13 libraries Volta-compatible.
* Runtime qualifications: NVML, a compiled `sm_70` CUDA kernel, PyTorch
  tensors/matmul, Ollama/llama.cpp, PyGPT, ComfyUI, and user-scoped Vulkan
  selection (Steam/Proton). Validate each separately from `nvidia-smi`.

## GPU display plan (operator-approved)

| Device | Desired role | Driver | Current change policy |
| --- | --- | --- | --- |
| Intel UHD 770 (i9-12900K) | Primary GNOME/Wayland desktop | `i915` | Enable as module; physically validate BIOS iGPU, display cabling, firmware, Wayland |
| AMD RX 570 | Auxiliary display/renderer and fallback | `amdgpu` | Keep as module and retain known-working boot/display path during initial tests |
| NVIDIA V100 32 GiB | CUDA inference, optional opt-in Vulkan | proprietary `nvidia` | Do not force primary DRM/display role |

An installed driver is not a GPU-role switch. Before promoting `stable`,
test actual motherboard video connectors, firmware iGPU multi-monitor settings,
`/sys/class/drm`, display enumeration, login/Wayland, multi-GPU render routing,
VA-API/Quick Sync, AMD fallback, and V100 isolation.
Keep RX 570 primary for the **first** test boot; switch desktop to UHD 770
only after that succeeds, then re-qualify and record the desired final layout.
Do not change live BIOS, display, kernel parameters, or login manager in build CI.

## Read-only hardware baseline capture

From the **separate feature-branch checkout**, before any kernel compilation:

```bash
bash scripts/kernel/huey-kernel-hardware-audit.sh \
  | tee "$HOME/huey-kernel-734-audit.txt"
cp "/boot/config-$(uname -r)" "$HOME/huey-kernel-current.config"
```

Both operations read the live system; `tee` and `cp` only create user-owned
report files. The script never installs, reboots, changes graphics routing,
reconfigures storage, or needs root. Review and redact any machine identifiers
or filesystem paths before sharing the output. Preserve the full original
configuration outside the Git repository; publish only a reviewed, minimized
profile fragment.

## Storage/boot blockers

A read-only inventory must distinguish Optane NVMe from Intel VMD/RST,
`mdadm` RAID, device mapper, LVM and Btrfs RAID. Record exactly which are
boot-critical. Preserve modules and initramfs helpers for root filesystem,
NVMe/VMD, AHCI, block integrity, encryption, mdraid/dm, ext4/Btrfs, UEFI,
microcode, input/display recovery. No RAID reshape, repartitioning, firmware
storage-mode changes, or bootloader writes as part of building.

## Acceptance criteria before promotion

1. Source signature/checksum, complete config diff, reproducible metadata,
   toolchain versions, image/headers packages and exact suffix all pass.
2. NVIDIA modules compile for the target kernel with correct vermagic, signing
   and runtime tests; no proprietary binary appears in public artifacts.
3. Three clean test boots, known-good default retained, rollback actually
   exercised by the operator.
4. All SATA/NVMe/Optane/RAID devices mount as expected, Btrfs and other
   filesystem checks report no new errors; boot-critical modules confirmed.
5. Intel CPU frequency/thermal/power control, firmware, network, USB and audio
   function without regressions.
6. UHD 770 works as the final primary desktop, RX 570 works as auxiliary,
   NVIDIA remains independently available as the compute GPU.
7. CUDA/PyTorch/Ollama/PyGPT/ComfyUI and opt-in Vulkan/Steam smoke tests pass
   with measured results compared against the last known-good kernel.
8. 24-hour controlled stability and journal/error checks. GPU-intensive tests
   must be deferred until V100 cooling is adequate: prior 87 C reached the
   observed slowdown threshold. No uncontrolled stress testing.
9. Hardware qualification and operator approval are recorded before rebuilding
   and signing the distinct `-huey-stable` artifact and verifying it again.

## Development workflow

Commit each pre-build code/config/test/documentation change on
`feature/huey-kernel-7.3.4`. Feature-branch CI runs *offline* lint/type/unit/
dry-run checks only. No driver downloads, secrets, kernel installation,
bootloader changes, GPU stress, live display changes or publishing vendor
software. Create the review PR after stable qualification as requested.
