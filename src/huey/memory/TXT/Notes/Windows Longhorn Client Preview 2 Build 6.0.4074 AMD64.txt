## Executive Summary

Windows Longhorn build 6.0.4074.idx02.040425-1535 ("Longhorn Client Preview 2") is the second and last widely distributed pre-reset Longhorn preview, provided to attendees at WinHEC 2004 (Seattle, May 4–7, 2004) as a developer-facing preview for hardware/driver ecosystem preparation. This build is historically "famous" because it is one of the clearest externally available snapshots of the pre-reset Longhorn vision — especially its composited desktop experiments and early "Aero" lineage — but those headline UI characteristics are primarily true of the x86 build rather than AMD64.

**Critical Verification Result:** For AMD64 specifically, BetaWiki's evidence-based cataloging explicitly states: *"It is worth to note that features related to .NET Framework, such as the sidebar, MIL effects or Aurora, do not work on the x64 version."* This is a major constraint if your goal is "the most Vista-like Longhorn."

For the stated must-have — PuTTY 0.83 — the evidence is encouraging but not absolute. PuTTY 0.83 (released 2025-02-08) explicitly restored Windows XP compatibility after 0.82 temporarily broke it. Since XP predates NT 6.0, this strongly suggests PuTTY 0.83 is conservative in its Win32 dependencies and should in principle run on Longhorn 4074 — especially if you use the standalone EXE instead of the MSI.

**Critical Correction:** PuTTY 0.83 now has **known security vulnerabilities** that were fixed in later releases (0.84 and 0.85). The official PuTTY release page states: *"This release has known security vulnerabilities. Consider using a later release instead, such as the latest version, 0.85."*

## 1. Introduction

Longhorn (the codename that ultimately became Windows Vista) is best understood as two projects separated by a substantial reset. The early ("pre-reset") branch attempted to deliver a set of "pillars" that Microsoft publicly described in 2003 as:

- **Avalon** (new presentation/graphics subsystem)
- **WinFS** (new storage subsystem)
- **Indigo** (new communications/Web-services subsystem)

At WinHEC 2004, Microsoft positioned Longhorn preview code as a practical on-ramp for OEMs and IHVs — especially to begin work on native Longhorn device drivers and to support forward-looking graphics/driver architectures. Build 4074 is the canonical artifact of that moment: it is explicitly described as the WinHEC 2004 "Preview 2" build distributed at the conference.

By August 2004, Microsoft publicly acknowledged schedule and scope changes (including shipping WinFS later) while targeting broad availability in 2006, reflecting the broader reset dynamics.

**In the Huey‑VistaBox context**, HueyOS is described as an offline-first OS/software layer coordinating local AI, tools, and hardware — currently grounded in a real Linux-first baseline. This architecture strongly suggests a Windows Longhorn guest should be treated as a **contained compatibility island** (e.g., legacy UI/driver research, "minimum x64 Windows" demonstrations, or controlled client tooling), not as a trusted operational node.

## 3. AMD64 UI Limitations (Verified)

### 3.1 BetaWiki's Explicit Statement

**Verification (BetaWiki):** *"It is worth to note that features related to .NET Framework, such as the sidebar, MIL effects or Aurora, do not work on the x64 version."*

### 3.2 Practical Comparison

| Capability Class | 4074 x86 (Documented) | 4074 AMD64 (Verified) | Operational Meaning |
|------------------|----------------------|----------------------|---------------------|
| **Sidebar tiles / managed shell surfaces** | Present and central | **Reported non-functional** | AMD64 will feel "less Longhorn" out of the box |
| **MIL-driven translucent surfaces** | "Complete MIL effects" | **Reported non-functional** | Avoid making DWM/MIL part of success criteria |
| **Aurora (or placeholder equivalent)** | Present in x86 narratives | **Reported non-functional** | Treat Aurora as non-goal on AMD64 |
| **Basic DWM enabling** | Documented pathway exists | **Possible via extensive workarounds** | DWM experimentation is brittle and optional |

**Note on Animated Preview Pane Aurora (APPA):** BetaWiki notes that it is possible to render an aurora effect in the preview pane, commonly known as Animated Preview Pane Aurora (APPA). However, this is distinct from the full desktop Aurora effect and requires modification to enable. The full desktop Aurora "wasn't functional in the original build" and "trying to load it throws errors because of outdated stuff."

## 4. NT 6.0 x64 Mechanics

### 4.1 WOW64 Constraints

Even if you ignore the "Vista-like" UI layer, the AMD64 build is still a real NT-family 64-bit OS and inherits the fundamental constraints of x64 Windows:

| Constraint | Description |
|------------|-------------|
| **WOW64** | Standard 32-bit compatibility subsystem on 64-bit Windows |
| **File system redirection** | Many 32-bit accesses targeting `%windir%\System32` are redirected to `%windir%\SysWOW64` |
| **No 16-bit Windows apps** | 64-bit Windows does not support 16-bit Windows applications |
| **No 32-bit kernel-mode drivers** | 64-bit Windows does not support 32-bit kernel-mode drivers |

**Implication:** A "modern-ish" 32-bit userland artifact like PuTTY 0.83 is conceptually compatible if WOW64 is present and stable. Anything requiring legacy 16-bit installers is a hard no. Any device integration requiring unsigned/32-bit drivers is a hard no.

## 5. Known Defects and Reliability Issues

### 5.1 Logon-Critical Services

**Verification (BetaWiki):** *"This build relies on Terminal Services and the User Profile Service to properly log users on. If Terminal Services are disabled or set to manual, the operating system hangs at a black screen with the watermark. If the User Profile Service is disabled or set to manual, the user will be able to log on, but Explorer will not be able to load properly, and profile-specific settings will be lost."*

### 5.2 DNS and Networking

**Verification (BetaWiki):** *"DNS requests might not work properly on certain network configurations when a DNS server is automatically acquired via DHCP. Configuring DNS manually fixes this problem."*

### 5.3 Multi-Core Hangs

**Verification (BetaWiki):** *"In some multi-core configurations and at random times, Windows hangs significantly rendering the operating system almost unusable a few seconds after logging in. The only solution is a hard reset."*

### 5.4 Timebomb Behavior

**Verification (BetaWiki):** *"It is one of the several Longhorn builds that has a timebomb set to evaluation mode that triggers after 180 days, and as such it can be installed on the current date. Once the timebomb is triggered, Windows immediately logs the user out and returns back to the logon screen if the user tries to logon."*

### 5.5 Additional Known Issues

| Issue | Description |
|-------|-------------|
| **Ctrl+Alt+Del hang** | Pressing at login prompt has a chance to hang system or cause 0x00000050/0x0000008E bugcheck |
| **CD/DVD insertion** | Sometimes crashes with UDF_FILE_SYSTEM |
| **Boot to desktop** | Sometimes crashes with 0x000000D1 |
| **Explorer sorting** | ZIP files sorted alongside folders; Control Panel sorted twice |
| **Explorer edits not persisting** | Top bar edits valid only for open window |

### 6.2 DWM Fragility

**Verification (BetaWiki):** DWM can render artifacts, black screens, or crashes depending on host hardware and VM settings. Multiple forum reports confirm that DWM requires extensive workarounds and is considered brittle.

### 6.3 longhorn.ms Operational Distinction

Community analysis notes that full VMware Tools may not be compatible, but extracted driver packages often are. Recommended approach: use extracted VMware 6.5.2-era driver packages rather than modern Tools.

## 7. PuTTY 0.83 Compatibility Assessment

### 7.1 Official Compatibility Evidence

**Verification (Official PuTTY Changelog):** *"Windows XP support was accidentally broken, and now reinstated."*

**Verification (Official PuTTY FAQ):** *"PuTTY 0.83 still runs on Windows XP – but the previous release 0.82 didn't."*

**Verification (PuTTY Wishlist Bug Record):** The 0.82 binaries failed on XP due to a manifest-related issue; this was fixed in 0.83.

### 7.2 Strategic Inference

If PuTTY 0.83 is engineered to remain compatible with Windows XP-era constraints, then it is likely to operate on Longhorn 4074's Win32 surface area as well — particularly as a standalone EXE — because Longhorn 4074 is still a classic Win32 desktop. This inference is supported indirectly by PuTTY's XP-compatibility posture and by Microsoft's general compatibility framing of WOW64 on x64 Windows.

### 7.3 Security Warning

**Critical Update (2026):** PuTTY 0.83 has known security vulnerabilities. The official release page states:

*"SECURITY WARNING: This release has known security vulnerabilities. Consider using a later release instead, such as the latest version, 0.85."*

Known vulnerabilities in 0.83 (fixed in 0.84 and 0.85):

| Vulnerability | Fixed In |
|---------------|----------|
| `ecdsa-remotely-triggerable-assertion` | 0.84 |
| `rsakex-double-free` | 0.84 |
| `telnet-trust-sigil` | 0.84 |
| `argon2-parameter-checks` | 0.85 |
| `etm-large-packet-overflow` | 0.85 |
| `maxpkt-0-tight-loop` | 0.85 |
| `pageant-deferred-decryption-uaf` | 0.85 |
| `ssh-greeting-unbounded` | 0.85 |

**Recommendation for Lab Use:** Given that this is a research VM in an isolated lab environment, the security vulnerabilities may be acceptable for functional testing purposes. However, the VM should **never** be connected to untrusted networks, and no secrets should be stored in the guest.

### 7.4 Installation Strategy

| Approach | Recommendation |
|----------|----------------|
| **MSI installer** | **Avoid** — Longhorn-era Windows Installer compatibility is a pain point |
| **Standalone EXE** | **Recommended** — x64 first, fall back to x86 if needed |
| **Rationale** | PuTTY 0.83 is deliberately conservative enough to still run on XP, implying it avoids newer dependency traps |

## 8. Recommendation: Is 4074 AMD64 the Right Choice?

### 8.1 Verdict

As an expert-to-expert judgment grounded in the verified evidence: **No — at least not on AMD64.**

Build 4074 x86 is the variant most associated with "complete" pre-reset MIL/DWM visual experiments. But the AMD64 build is **explicitly documented as missing/breaking core managed UI features** (Sidebar/MIL/Aurora), which are central to that "Vista-like Longhorn" identity.

### 8.2 When 4074 AMD64 Is Defensible

If your actual goal is "minimum 64-bit Windows OS that can run PuTTY," 4074 AMD64 can still be defensible because:

1. It is a real NT 6.0 x64 environment (useful architecturally as a boundary case)
2. It has a strong historical pedigree and well-documented quirks
3. You can design Huey‑VistaBox around PuTTY + a small controlled toolset, not around Longhorn eye-candy

### 8.3 Better Alternatives for "Vista-like" on AMD64

| Build | Era | Notes |
|-------|-----|-------|
| **5048** | Post-reset (WinHEC 2005) | More XP/2003-like; AMD64 compile available |
| **5112** | Vista Beta 1 | DWM can be enabled with known workarounds |
| **5384.4** | Vista Beta 2 | Closest to Vista UX; more mature driver/software posture |

## 9. Security and Lab Governance

Even though Longhorn 4074 is a research target, it should be treated as high-risk software:

| Risk | Mitigation |
|------|------------|
| **Unsupported OS** | No modern security updates; CISA guidance confirms higher compromise risk |
| **Network exposure** | Keep behind NAT or host-only networking; avoid bridged exposure |
| **Data storage** | Never store secrets in the guest |
| **Guest tools** | Treat the VM as untrusted; no personal accounts |
| **PuTTY 0.83 vulnerabilities** | Acceptable only in isolated lab; never connect to untrusted networks |

---

## 10. Conclusion

Windows Longhorn 6.0.4074 AMD64 is a historically significant WinHEC 2004 preview build with a well-mapped defect surface, making it a legitimate candidate for a research VM and a "minimum NT 6.0 x64" demonstration OS.

However, it is **not** the best choice if your primary criterion is "most polished / Vista-like Longhorn," because the AMD64 build is **explicitly documented as lacking functional Sidebar/MIL/Aurora features** that define the famous 4074 experience.

For the PuTTY requirement, PuTTY 0.83 is a strategically good target because it intentionally maintains XP compatibility and offers standalone executables — which is exactly the posture you want when you cannot trust MSI/installer stacks in a pre-release OS. Note that PuTTY 0.83 has known security vulnerabilities; in an isolated lab VM, this may be acceptable, but the VM should never be connected to untrusted networks.

The primary engineering work in Huey‑VistaBox will likely be **network stabilization** (manual DNS, conservative VM NIC choices) and **service discipline** (do not disable logon-critical services).
