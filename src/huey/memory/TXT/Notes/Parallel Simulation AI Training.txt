## 1. Introduction

Training an AI to beat a *Crash Bandicoot 1* speedrun involves combining demonstration learning with reinforcement learning (RL) and efficient use of emulation. The goal is to feed a "perfect run" (a predetermined sequence of controller inputs that completes a level quickly) into the system, and then have the AI improve upon it — i.e., learn from the example and attempt to surpass the timing.

Key components include:
- Using an emulator (or modded console) to run the game
- Leveraging Python-based AI frameworks (such as OpenAI's Gym/Stable-Baselines)
- Running parallel simulations to speed up learning

---

## 2. Emulation vs. Modded Hardware for AI Control

### 2.1 Emulation Advantages

| Advantage | Description |
|-----------|-------------|
| **Deterministic Environment** | Emulators can run the game deterministically (same input sequence produces same outputs) and allow saving/loading state |
| **Programmatic Input** | Emulator APIs or scripting allow injecting controller inputs frame-by-frame from Python |
| **Parallel Instances** | Multiple instances or threads of the emulator can run for parallel simulation |
| **Fast-Forward** | Emulators support fast-forwarding or removing frame limits, speeding up simulations |

**Verification:** Stable-Retro lets you "turn classic video games into Gymnasium environments for reinforcement learning" and supports platforms including Sega Master System/Genesis/CD/32X/Saturn/Dreamcast, NES, SNES, Nintendo 64/DS, Atari 2600, Arcade Machines and more.

### 2.2 Emulation vs. Physical Console

| Factor | Emulator | Modded PS1 |
|--------|----------|------------|
| **Determinism** | Yes (save states, exact replay) | No |
| **Speed** | Can fast-forward | Real-time only |
| **Parallelization** | Multiple instances | Single instance |
| **Data Access** | Full RAM/state access | Requires hardware interfaces |
| **Complexity** | Low | High |

**Conclusion:** While a modded PS1 could theoretically be used to demonstrate the final learned controller sequence (for example, by feeding the AI's inputs into the console to showcase a perfect play on real hardware), all training and experimentation are best done in an emulator environment for speed and convenience.

## 3. Feeding a Predetermined "Perfect Run" (Demonstration)

### 3.1 Recording and Playback

Using the emulator, you can record the button inputs of the perfect run. Stable-Retro allows creating a `.bk2` movie file which stores the initial game state and the sequence of button presses. Because the emulator is deterministic, playing back this file reproduces the exact run every time. The recorded run can serve as ground truth data.

### 3.2 Imitation Learning (Behavioral Cloning)

One approach is to train a model to mimic the demonstration. For example, one could use behavioral cloning, treating the recorded states (game screens or memory states) and actions (controller inputs) from the perfect run as training data.

**Verification (pybandicoot):** A community project "pybandicoot" took this approach: it collected thousands of frames of Crash Bandicoot gameplay with corresponding keystrokes and trained a CNN to play the first level. The imitation model got surprisingly far (reportedly ~75% through the level on its own) by following the patterns it learned.

However, pure imitation has limitations — the agent might fail if it strays off the demonstrated trajectory, since it hasn't learned how to recover or try new strategies.

### 3.3 Using Demonstrations in Reinforcement Learning

A more powerful technique is to combine the demonstration with RL, so the agent can surpass the demonstrator.

**Verification (NAC):** "We propose a unified reinforcement learning algorithm, Normalized Actor-Critic (NAC), that effectively normalizes the Q-function, reducing the Q-values of actions unseen in the demonstration data. NAC learns an initial policy network from demonstrations and refines the policy in the environment, surpassing the demonstrator's performance".

In practical terms for Crash Bandicoot:
1. Initialize the agent's policy using the perfect run data
2. Let the agent experiment with variations in a simulated environment
3. Find even faster routes or glitch exploits

**Reward Design:**
- Small negative reward each time-step (encourages speed)
- Large positive reward at level completion
- Bonus for finishing in fewer frames than the demonstration

## 4. Integrating Python and OpenAI Tools

### 4.1 OpenAI Gym/Stable-Retro Environment

Using the Gym interface for the game is highly recommended. With Stable-Retro, you can integrate Crash Bandicoot as a custom environment.

**Verification:** Stable-Retro provides an example using Proximal Policy Optimization (PPO) from Stable Baselines 3:
```python
import stable_retro as retro
from stable_baselines3 import PPO
from stable_baselines3.common.vec_env import SubprocVecEnv
```

### 4.2 Stable-Baselines3 (SB3)

SB3 is a high-level library providing implementations of algorithms like PPO, DQN, etc., that work with Gym environments.

**Verification:** A recent project demonstrated exactly this: an AI learned to play Crash Bandicoot (the first level) using Stable-Retro + Stable-Baselines (PPO) as the tech stack.

### 4.3 Action Space Discretization

Controlling a PS1 game involves a potentially complex action space (D-pad, buttons, etc.). You will likely want to discretize the action space:
- Run forward
- Run forward + jump
- Spin attack
- etc.

**Verification:** Gym Retro allows custom discretizers to map the many-button binary space into a simpler set of actions.

## 5. Parallel Simulation for Faster Learning

### 5.1 Multiple Environments in Parallel

Instead of training on one game instance step-by-step, you can launch multiple parallel Crash Bandicoot environments and have the agent interact with all of them concurrently.

**Verification:** Stable-Baselines3 provides `SubprocVecEnv` which "Executes each environment in a separate process, enabling true parallelism" and is recommended for "Computationally expensive environments (physics simulations, 3D games)".

**Example:**
```python
from stable_baselines3.common.env_util import make_vec_env
from stable_baselines3.common.vec_env import SubprocVecEnv

env = make_vec_env("CrashBandicoot-PS1", n_envs=8, vec_env_cls=SubprocVecEnv)
model = PPO("CnnPolicy", env)
```

### 5.2 Faster Convergence

With parallel environments, the training algorithm can update the model with a larger batch of diverse experiences at once.

**Verification (FastTD3):** "We introduce FastTD3, a simple, fast, and capable RL algorithm that significantly speeds up training for humanoid robots... Our recipe is remarkably simple: we train an off-policy TD3 agent with several modifications – parallel simulation, large-batch updates, a distributional critic, and carefully tuned hyperparameters".

**Verification:** FastTD3 "solves a range of HumanoidBench tasks in under 3 hours on a single A100 GPU".

### 5.3 Distributed or Cloud Simulation

For larger scale, you could distribute the workload across multiple machines or use cloud instances to run dozens of parallel game simulations.

### 5.4 Use in Evolutionary Algorithms

If using a genetic algorithm or other search method, parallel simulation is also vital. A genetic algorithm would evaluate a population of runs in each generation, and those evaluations can be done in parallel on multiple emulator instances.

## 6. Additional Considerations

### 6.1 State Representation & Rewards

| Option | Description | Trade-off |
|--------|-------------|-----------|
| **Raw Pixels** | General but requires deep CNN | High computational cost |
| **RAM State** | Direct access to player coordinates | Requires memory address discovery |
| **High-Level Features** | Hand-crafted features | Requires domain knowledge |

**Reward Shaping:** Time to finish is the primary objective. A common reward shaping is -1 per step and +100 at level completion, so the agent is incentivized to finish in as few steps as possible.

### 6.2 Handling Complexity

Crash Bandicoot's mechanics (running, jumping, spinning, timing cycles of hazards) are quite complex. The AI might require a fairly large neural network and a lot of training to master the level. Using the demonstration will give it a huge head-start, but expect some training time to fine-tune behaviors.

### 6.3 Existing Projects and Resources

| Resource | Description |
|----------|-------------|
| **CrashBandicootRL** | GitHub project integrating PS1 games into Gym Retro with PPO |
| **my_retro** | Integration files for Crash (memory addresses for crates, end-of-level) |
| **Stable-Retro Documentation** | Guides on adding new games and training scenarios |
| **RetroArch Fork** | Machine learning support for real-time model control |

### 6.4 Using Real Hardware

If after training your AI policy you want to see it run on a real PlayStation, it is possible but requires some creativity.

**Verification (TASBot):** "TASBot is best described as a special R.O.B. robot holding a replay board connected to a game console's controller ports for the purposes of playing video games perfectly". The replay board "takes a predetermined list of inputs from a Linux machine and uses them to send signals directly to a console's controller ports".

**Note:** This would be a replay of the sequence, not live AI decision-making. Getting game state from a real console in real-time is very difficult without instrumentation.

### 6.5 Ethical/Community Aspect

Tool-assisted speedrun communities sometimes debate AI usage. A fully AI-discovered speedrun (especially if it finds new glitches) is an exciting development, but some TAS enthusiasts note that TAS runs are usually a collaborative, manual effort — an AI might "miss the point" of human ingenuity.

## 7. Implications for Monkey-Head-Project

The parallel simulation approach for Crash Bandicoot serves as a **reference implementation** for the Monkey-Head-Project's AI training infrastructure:

| Aspect | Relevance |
|--------|-----------|
| **Parallel Environments** | SubprocVecEnv pattern applicable to PyHuey training |
| **Demonstration Learning** | NAC-style algorithms for bootstrapping agents |
| **Emulator Integration** | Gym/Stable-Retro pattern for game environments |
| **Distributed Training** | FastTD3-style parallel simulation for speed |
| **Hardware Replay** | TASBot pattern for real-world validation |

**LabTech Recommendation:** For AI training involving game environments, use Stable-Retro with Stable-Baselines3 and SubprocVecEnv for parallel simulation. For demonstration learning, consider NAC or similar algorithms that can surpass demonstrator performance. For real-hardware validation, the TASBot replay board pattern provides a proven approach.
