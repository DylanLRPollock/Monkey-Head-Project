## Executive Summary

This document outlines a design for an expandable, modular cloud OS using Docker containers for application isolation and K3s (lightweight Kubernetes) for orchestration across heterogeneous Mac hardware. The goal is to create a unified Debian "Trixie" Linux environment with a full MATE desktop, accessible remotely via X2Go, running on top of existing macOS installations through virtualization.

## 1. Introduction

Creating an expandable and modular cloud OS means designing a computing environment that isn't tied to a single machine, but can span multiple devices, scale with additional hardware, and run various services in a flexible, isolated way. This paper outlines how to build such a system using two Apple computers as a starting point: a 2019 MacBook Pro (Core i9, 32 GB RAM, 1 TB SSD) and a 2017 iMac 5K (48 GB RAM, 1 TB Fusion Drive).

The goal is to leverage these powerful machines to run a unified Debian Trixie Linux environment on top of the existing macOS, complete with a full MATE desktop GUI accessible remotely. Docker containers provide modularity, and K3s provides orchestration, enabling the system to easily expand as more hardware (such as a Supermicro X9QRi-F+ server planned as a storage/backup node) is added.

**Design Benefits:**
- **Consistent "cloud desktop" experience** — Access the same Debian-based desktop from any device
- **Containerization** — Each service is isolated and portable
- **Orchestration** — Kubernetes distributes containers across machines and scales them

## 2. Hardware and Network Setup

### 2.1 Hardware Overview

| Machine | CPU | RAM | Storage | Role |
|---------|-----|-----|---------|------|
| 2019 MacBook Pro | Intel Core i9 (6/8-core) | 32 GB | 1 TB SSD | Worker node (portable) |
| 2017 iMac 5K | Intel Core i7 (quad-core) | 48 GB | 1 TB Fusion Drive | Master node (always-on) |
| Supermicro X9QRi-F+ (planned) | Quad Intel Xeon E5-4600 | Up to 1 TB | Many drives | Storage/backup hub |

**Verification Note:** The Supermicro X9QRi-F+ is a quad-socket LGA 2011 motherboard supporting Intel Xeon E5-4600 family processors. It has 32 DIMM slots (8 per CPU), supports up to 1 TB of DDR3 ECC Registered RAM, and offers dual Gigabit Ethernet, PCIe 3.0 expansion slots, and RAID 0/1/5/10 support.

### 2.2 Networking Configuration

A wired Gigabit Ethernet network connects the machines. The MacBook Pro requires a Thunderbolt or USB-C to Ethernet adapter. Static IP addresses (or reserved DHCP leases) simplify cluster setup. Verify connectivity with `ping` between nodes and configure macOS firewall rules to allow cluster traffic.

**Key Ports for K3s:**
- **6443/TCP** — Kubernetes API server
- **8472/UDP** — Flannel VXLAN overlay network
- **10250/TCP** — Kubelet API

### 2.3 Future Expansion

The Supermicro server can join the cluster as a worker node or operate as a dedicated storage server. It can host:
- **Longhorn or Ceph** distributed storage
- **NFS shares** for Kubernetes PersistentVolumes
- **Heavy compute workloads** (AI model serving, batch jobs)

## 3. Base OS: Debian Trixie with MATE Desktop

### 3.1 Debian Trixie

Debian 13 "Trixie" is the current stable release (initial release August 9, 2025; current point release 13.7 as of September 2026). It includes MATE 1.26.1 as the desktop environment.

**Verification:** The document's claim that Debian Trixie is "the latest release of Debian as of 2025" is accurate. The current point release is 13.7 (September 2026).

### 3.2 Running Debian on Mac Hardware

Since the Macs run macOS, Debian runs in a virtual machine using a hypervisor (VirtualBox, VMware Fusion, Parallels, or UTM/QEMU).

| Approach | Use Case |
|----------|----------|
| **Virtual Machine** | Full desktop OS experience with MATE |
| **Container** | Lightweight, but desktop GUI is complex |

**Recommended allocation:**

| Machine | CPU Cores | RAM | Notes |
|---------|-----------|-----|-------|
| MacBook Pro VM | 4–8 | 16 GB | Leaves resources for macOS |
| iMac VM | 8 | 32 GB | Higher RAM available |

### 3.3 MATE Desktop

MATE 1.26 is a continuation of the classic GNOME 2 interface — lightweight, efficient, and well-supported in Debian.

### 3.4 Remote Desktop Access

| Solution | Protocol | Advantages |
|----------|----------|------------|
| **X2Go** | NX over SSH | Efficient, supports MATE, session resuming, secure |
| **VNC** | RFB | Simpler, but slower and less secure |
| **RDP (xrdp)** | RDP | Integrates with Windows/Mac clients |

**Verification:** X2Go is known to work fine with MATE out of the box (with compositing disabled for performance).

## 4. Docker for Modular Components

### 4.1 Why Docker?

Docker provides operating-system-level virtualization — more lightweight than full VMs. Containers share the host kernel but isolate application processes and dependencies.

**Verification:** Docker containers are generally faster and less resource-intensive than full virtual machines.

### 4.2 Modular Components

| Component | Example Container |
|-----------|-------------------|
| AI services | LLM inference server (PyTorch/TensorFlow) |
| Data storage | PostgreSQL, MongoDB |
| Web interface | Nginx, Node.js |
| Background jobs | Scheduled tasks, file sync |

### 4.3 Docker Setup

Install Docker Engine within the Debian Trixie VMs. Each node runs its own Docker daemon; Kubernetes unifies management.

**macOS Note:** Docker Desktop for Mac is an alternative, but running Docker inside Linux VMs is preferred for full Linux kernel compatibility.

## 5. Kubernetes Cluster Orchestration

### 5.1 Choosing K3s

K3s is a lightweight, CNCF-certified Kubernetes distribution packaged as a single binary under 100 MB. It is ideal for edge, homelab, and IoT environments.

**Critical Correction:** K3s is **Linux-only** and does not run natively on macOS. On macOS, you must either:
1. Run K3s inside a Linux VM (as described in this document)
2. Use **k3d** (K3s in Docker) for development/testing

### 5.2 K3s Installation

**On the master node (iMac's Debian VM):**
```bash
curl -sfL https://get.k3s.io | sh -
```

This creates a single-node Kubernetes cluster with an embedded SQLite datastore.

**On the worker node (MacBook's Debian VM):**
```bash
export K3S_URL="https://<MasterNodeIP>:6443"
export K3S_TOKEN="<join token from master>"
curl -sfL https://get.k3s.io | sh -
```

**Verification:** K3s single-node installation is fully functional, including datastore, control-plane, kubelet, and container runtime.

### 5.3 K3s Networking

K3s uses Flannel for the overlay network, Traefik for ingress, and ServiceLB for load balancing. Containers on different hosts communicate as if on one network.

### 5.4 Cluster State and Storage

K3s uses SQLite by default. Back up cluster state before major changes. For future HA, consider etcd or MySQL as external datastore.

## 9. Conclusion

This design provides a comprehensive plan for constructing a personal expandable, modular cloud OS using existing hardware and modern container orchestration tools. By using Debian Trixie with MATE, Docker for modularity, and K3s for orchestration, the system achieves:

- **Unified computing** across heterogeneous Mac hardware
- **Modular services** that can be updated independently
- **Scalability** — new nodes join with minimal reconfiguration
- **Remote access** via X2Go

The architecture is prepared for future integration of the Supermicro X9QRi-F+ server, which will add massive storage and compute capacity. Security should be maintained through SSH tunnels, firewall rules, and regular updates.
