# 2.5-inch SATA SSD vs M.2 NVMe SSD: Performance Comparison

**Technical Reference Document**
**Document Version:** 1.0
**Status:** Verified
**Last Updated:** 2026-09-26
**Cross-Reference:** V206 Master Plan — Storage Architecture

---

## Executive Summary

M.2 NVMe SSDs substantially outperform 2.5-inch SATA SSDs across sequential throughput, random I/O, and latency. However, the practical impact depends heavily on workload type. For the Monkey-Head-Project's V206 storage architecture, this distinction matters: the **Intel Optane M10 16GB drives selected for the OS pool are NVMe devices**, while the **10TB Western Digital NAS drives are mechanical HDDs**. Understanding the NVMe vs SATA distinction clarifies why the OS pool uses M.2 NVMe while the data pool uses SATA-connected HDDs.

**Important Correction:** Intel Optane M10 devices are **memory devices, not storage devices**, and cannot be used to set up RAID volumes or accelerate them. The V206 plan to use four M10 drives in a RAID 10 array requires verification of RAID controller compatibility and whether the M10's role is as OS storage or as cache acceleration.

---

## 1. Interface and Bandwidth

### 1.1 SATA III

Traditional 2.5-inch SSDs use the **SATA III** interface, with a maximum link throughput of **6 Gb/s**. Due to 8b/10b encoding and protocol overhead, the practical limit is approximately **550 MB/s** for reads and **500–530 MB/s** for writes.

| Parameter | Value |
|-----------|-------|
| Interface | SATA III (6 Gb/s) |
| Encoding | 8b/10b |
| Theoretical max | 600 MB/s |
| Practical max | ~550 MB/s |
| Queue depth | Single queue, 32 commands |
| Protocol | AHCI (designed for HDDs) |

### 1.2 PCIe NVMe

M.2 NVMe SSDs connect via the **PCI Express bus**, bypassing SATA/AHCI entirely. Each PCIe lane provides roughly **1 GB/s** of bandwidth, and NVMe drives typically use **x4 lanes**:

| PCIe Generation | Lanes | Theoretical Bandwidth | Typical NVMe Speeds |
|-----------------|-------|----------------------|---------------------|
| PCIe 3.0 | x4 | ~4 GB/s | 3,000–3,500 MB/s read |
| PCIe 4.0 | x4 | ~8 GB/s | 5,000–7,450 MB/s read |
| PCIe 5.0 | x4 | ~16 GB/s | 10,000–14,000+ MB/s read |

NVMe uses a purpose-built protocol supporting up to **64K queues with 64K commands each**, enabling massive parallelism compared to SATA's single queue of 32 commands.

**Verified:** PCIe 3.0 x4 NVMe drives commonly reach **3,500 MB/s sequential read** and **3,000 MB/s sequential write**.

## 2. Sequential Read/Write Speeds

### 2.1 SATA III Ceiling

Even the fastest SATA SSDs are capped by the interface. The Samsung 870 EVO — a high-end SATA drive — is rated at **560 MB/s read** and **530 MB/s write**, essentially at the SATA III ceiling.

### 2.2 NVMe Performance Tiers

| Tier | Interface | Sequential Read | Sequential Write | Example |
|------|-----------|----------------|------------------|---------|
| Entry NVMe | PCIe 3.0 x4 | ~2,000–3,500 MB/s | ~1,000–3,000 MB/s | WD Blue SN570 |
| Mid NVMe | PCIe 3.0 x4 | ~3,500 MB/s | ~3,000 MB/s | WD Black SN750 |
| High NVMe | PCIe 4.0 x4 | ~5,000–7,450 MB/s | ~4,500–6,900 MB/s | Samsung 990 Pro |
| Enthusiast | PCIe 5.0 x4 | ~10,000–14,000 MB/s | ~10,000+ MB/s | Latest Gen5 |

**Verified:** Samsung 990 Pro (PCIe 4.0) is rated at **7,450 MB/s read** and **6,900 MB/s write** — over **13× the throughput of SATA's ~560 MB/s**.

### 2.3 Practical Impact

| File Size | SATA SSD (~550 MB/s) | PCIe 3.0 NVMe (~3,000 MB/s) | PCIe 4.0 NVMe (~6,500 MB/s) |
|-----------|---------------------|-----------------------------|-----------------------------|
| 10 GB | ~18 sec | ~3 sec | ~1.5 sec |
| 50 GB | ~91 sec | ~17 sec | ~8 sec |
| 100 GB | ~182 sec | ~33 sec | ~15 sec |

## 3. Random I/O Performance (IOPS)

### 3.1 SATA IOPS Limits

SATA SSDs are constrained by the AHCI protocol. The Samsung 870 EVO is rated at approximately **98,000 random read IOPS** and **88,000 random write IOPS** (4KB, QD32).

### 3.2 NVMe IOPS Capability

NVMe drives exploit parallel queueing to achieve order-of-magnitude gains:

| Drive | Random Read IOPS | Random Write IOPS |
|-------|-----------------|-------------------|
| SATA (Samsung 870 EVO) | ~98,000 | ~88,000 |
| Entry NVMe (PCIe 3.0) | ~275,000 | ~300,000 |
| High NVMe (Samsung 990 Pro) | **1,200,000–1,600,000** | **1,550,000** |

**Verified:** Samsung 990 Pro is rated for up to **1,400,000 random read IOPS** and **1,550,000 random write IOPS**.

### 3.3 Why This Matters

In multi-user or VM environments, NVMe can service many more IO requests in parallel. For the Monkey-Head-Project's **four V100 GPUs loading large model weights**, high IOPS matters during concurrent model initialization.

## 4. Latency Differences

### 4.1 Protocol Overhead

SATA/AHCI incurs higher per-command overhead because it was designed for slow spinning disks. NVMe communicates directly with the CPU via the PCIe bus.

| Metric | SATA (AHCI) | NVMe |
|--------|-------------|------|
| Command latency | ~6 μs | ~2.8 μs |
| I/O request latency | 50–100 μs | 10–50 μs |
| Best-case latency | ~100 μs | <10 μs |

**Verified:** Kingston's technical documentation confirms AHCI has a latency of **6 microseconds** while NVMe has **2.8 microseconds**, and NVMe communicates directly with the system CPU.

### 4.2 Real-World Impact

Lower latency translates to snappier system responsiveness, particularly in **low-queue-depth scenarios** like OS boot and application launches. For the Monkey-Head-Project's **PyHuey operator interface**, this means faster response times during interactive use.

## 5. Thermal Performance and Throttling

### 5.1 SATA Thermal Profile

2.5-inch SATA SSDs operate at lower speeds and have larger surface areas for heat dissipation. Overheating is **virtually a non-issue** under normal use.

### 5.2 NVMe Thermal Profile

M.2 NVMe drives generate significant heat during sustained high-speed operation:

| Condition | Temperature Range |
|-----------|------------------|
| Idle | 30–45°C |
| Normal load | 45–65°C |
| Heavy sustained load | 60–80°C |
| Throttling threshold | ~70–80°C |

**Verified:** Most NVMe SSDs run safely between **30°C and 70°C** under load, with throttling typically starting around **80°C** to protect the controller. Consumer SSDs are designed to operate safely between **0°C and 70°C**, with throttling beginning at approximately **70°C**.

### 5.3 Mitigation

- Use motherboard M.2 heatsinks
- Ensure adequate case airflow
- Consider thermal pads for sustained workloads

For the Monkey-Head-Project's V4 shell, the **Thermaltake Mozart case** must provide adequate airflow across M.2 slots, especially given the density of components (four V100 GPUs + motherboard + PSUs).

## 6. Impact on Real-World Applications

### 6.1 Operating System Boot Time

| Scenario | HDD | SATA SSD | NVMe SSD |
|----------|-----|----------|----------|
| Windows 11 cold boot | ~50 sec | ~14 sec | ~12 sec |
| Windows 10 boot | — | ~36 sec | ~16 sec |

**Verified:** Real-world testing shows Windows 11 booting in **14.3 seconds** on SATA SSD vs **12.2 seconds** on M.2 NVMe. The difference is **1–3 seconds** — noticeable but not dramatic.

### 6.2 Gaming Load Times

| Game Type | SATA SSD | NVMe SSD | Improvement |
|-----------|----------|----------|-------------|
| Light esports (CS2) | ~8 sec | ~4 sec | 2× |
| Open world (Cyberpunk 2077) | ~1,200–1,500 ms | ~300 ms | 4–5× |
| Total War: Warhammer III | ~22.5 sec | ~17 sec | ~25% |

**Verified:** NVMe typically cuts game level load times by **30–50%** compared to SATA SSDs, though some titles show only 1–3 seconds of difference.

### 6.3 Large Dataset Processing

For the Monkey-Head-Project's **128GB VRAM model loading**, storage speed directly impacts initialization time:

| Dataset Size | SATA SSD | PCIe 4.0 NVMe |
|--------------|----------|---------------|
| 50 GB | ~91 sec | ~8 sec |
| 100 GB | ~182 sec | ~15 sec |
| 400 GB (V100 model weights) | ~12 min | ~1 min |

**Verified:** Reading a 100GB dataset takes approximately **3 minutes** from SATA SSD (~550 MB/s) but **under a minute** on Gen4 NVMe (~7 GB/s).

## 7. Implications for Monkey-Head-Project V206

### 7.1 OS Storage: Intel Optane M10 RAID 10

The V206 plan specifies **four Intel Optane M10 16GB drives in RAID 10** for the OS pool.

**Critical Correction:** Intel Optane M10 devices are classified as **memory devices, not storage devices**, and according to Intel's official documentation, **cannot be used to set up RAID volumes or accelerate them**.

**Required Action:**
1. Verify whether the M10 drives can function as standalone boot drives outside Intel's officially supported configurations
2. Confirm RAID controller compatibility (the ASUS TUF Gaming Z790-Plus WiFi may not support RAID 10 on M.2 slots)
3. Consider alternative OS storage if RAID 10 is infeasible

### 7.2 Data Storage: 10TB HDDs in RAID 1

The 10TB Western Digital NAS drives are **mechanical HDDs** connected via SATA. Their sequential throughput (~200 MB/s) is well below SATA SSD limits, but their role is **redundant bulk storage**, not high-speed access.

### 7.3 PCIe Lane Allocation

The V206 architecture uses **all five PCIe devices via extenders** (four V100 GPUs + one discrete GPU). This may leave limited PCIe lanes for M.2 NVMe slots. The ASUS Z790-Plus WiFi has:

- **CPU-connected M.2 slots**: Typically 1–2 slots
- **Chipset-connected M.2 slots**: Additional slots, but shared bandwidth

**Critical Question:** Can the motherboard support four M.2 NVMe drives simultaneously while also routing five PCIe devices through extenders? This requires verification of PCIe lane availability.

## 8. Conclusion

| Metric | SATA SSD | NVMe SSD | Advantage |
|--------|----------|----------|-----------|
| Sequential read | ~550 MB/s | 3,000–14,000 MB/s | **5–25×** |
| Sequential write | ~500 MB/s | 2,000–10,000 MB/s | **4–20×** |
| Random read IOPS | ~100K | 300K–1.6M | **3–16×** |
| Random write IOPS | ~90K | 300K–1.55M | **3–17×** |
| Latency | 50–100 μs | 10–50 μs | **2–10×** |
| Thermal risk | Low | Moderate–High | SATA |
| Cost per GB | Higher | Lower | NVMe |

**For the Monkey-Head-Project:**

- **OS pool:** NVMe is appropriate for fast boot and PyHuey responsiveness, but **Intel Optane M10 RAID 10 requires verification** due to Intel's official limitation on RAID usage.
- **Data pool:** HDDs in RAID 1 are appropriate for bulk storage where capacity and redundancy matter more than speed.
- **Model loading:** NVMe significantly reduces the time to load large model weights into VRAM, which matters for the four V100 GPUs.

## Appendix B: Glossary

| Term | Definition |
|------|------------|
| **AHCI** | Advanced Host Controller Interface — SATA protocol designed for HDDs |
| **NVMe** | Non-Volatile Memory Express — protocol designed for flash storage |
| **PCIe** | Peripheral Component Interconnect Express — high-speed serial bus |
| **IOPS** | Input/Output Operations Per Second — random access performance metric |
| **Queue Depth** | Number of pending commands a drive can process in parallel |
| **Thermal Throttling** | Speed reduction to prevent overheating |
| **SLC Cache** | Fast single-level cell buffer that absorbs burst writes |
