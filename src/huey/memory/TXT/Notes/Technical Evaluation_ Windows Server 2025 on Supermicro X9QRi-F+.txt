Technical Evaluation: Windows Server 2025 on
Supermicro X9QRi-F+
Overview of Windows Server 2025 Features
Windows  Server  2025  is  the  latest  Long-Term  Servicing  Channel  (LTSC)  release  (generally  available
November 2024) and builds upon Windows Server 2022 with significant enhancements in virtualization,
storage, security, and hybrid management
. Microsoft highlights “major advancements across the board
for Hyper-V, GPU integration, Storage Spaces Direct (software-defined storage), software-defined networking, and
clustering,” making  Windows  Server  2025  a  strong  platform  for  modern  workloads  requiring  high
performance and scalability
. Below is an overview of core features and improvements, especially in the
areas of virtualization, storage, security, and remote management, that are relevant to deploying Windows
Server 2025 on a Supermicro X9QRi-F+ based system. 
Virtualization and Hyper-V Enhancements
Hyper-V Scalability: Windows Server 2025 dramatically increases virtualization scale. A single host
now supports up to 2,048 logical processors and 4 PB of physical memory (up from 512 LP / 48 TB in
Server 2022)
. Individual Generation 2 VMs can be configured with up to 240 TB of RAM and 2,048
virtual CPUs
. This far exceeds the hardware limits of the X9QRi-F+ (which maxes out at 4 CPUs
and ~1 TB RAM) and ensures the OS can fully utilize all resources the board provides. 
Enhanced Hyper-V Features: Several new Hyper-V capabilities improve performance and flexibility.
Dynamic Processor Compatibility mode has been improved for clusters – it now dynamically uses
the maximal CPU feature set common to all hosts, yielding better VM performance when live-
migrating across different CPU generations
. Accelerated Networking (AccelNet) simplifies
SR-IOV networking for VMs, automatically configuring host networking to use the high-performance
SR-IOV datapath and thereby reducing VM network latency, jitter, and host CPU overhead
(note: SR-IOV requires a capable NIC; see hardware notes below). By default, new VMs created via
Hyper-V Manager are now Generation 2 for better security and performance
. 
GPU Partitioning and AI Workloads: Windows Server 2025 introduces improved GPU virtualization.
Through GPU Partitioning (GPU-P), a physical GPU can be partitioned and shared across multiple
VMs, each VM getting a dedicated fraction of the GPU’s resources
. New high-availability support
allows a VM using GPU-P to fail over to another node, and  live migration is supported for GPU-
partitioned VMs, enabling movement of GPU-accelerated workloads without downtime
. These
features  are  aimed  at  AI/ML  and  graphics  workloads.  (On  the  X9QRi-F+,  GPU-P  would  require
installing a modern GPU since the board’s onboard video is a basic 2D controller.) 
Hyper-V Security: Hypervisor-Enforced Paging Translation (HVPT) is a new security feature that
protects critical kernel page tables from modification by malicious code, helping prevent certain
buffer  overflow  attacks
.  It  is  enabled  by  default  on  supported  hardware.  Additionally,

Clustering and Availability: Windows Server 2025 improves clustering for Hyper-V. Notably, it

Storage and Data Management Improvements
Faster Storage I/O (NVMe Optimizations): Windows Server 2025 is tuned for high-speed NVMe
SSDs. In fact, Microsoft reports that on identical hardware, Server 2025 delivers up to 60% higher
storage IOPS throughput compared to Windows Server 2022
. This is achieved through kernel
optimizations that reduce NVMe latency and CPU overhead
. On a Supermicro X9QRi-F+, which
natively offers 6 SATA ports (2 × SATA3 6Gb/s + 4 × SATA2)
, using NVMe would require a PCIe
adapter. While the board itself doesn’t have M.2 slots, it does support NVMe drives via PCIe – and
Windows Server 2025 will leverage those drives more efficiently than previous OS versions. 
Resilient File System (ReFS) Enhancements: Server 2025 brings major updates to ReFS aimed at
performance and space efficiency.  Block Cloning is now supported on ReFS (notably used by the
new Dev Drive feature), which dramatically speeds up file copy operations by copying data block
references in metadata instead of reading/writing the actual blocks
. This yields faster large
file  copies  and  reduced  I/O  –  beneficial  for  virtual  disk  cloning,  backups,  or  VM  provisioning.
Additionally, ReFS gains native data deduplication and compression support, allowing storage of
redundant data more efficiently on ReFS volumes
. This brings ReFS closer to feature-parity with
NTFS for general file server use. 
Storage Spaces Direct and Replica: In clustered storage, Storage Spaces Direct (S2D) is improved
with  thin-provisioned volumes. Administrators can now create S2D volumes that only consume
physical capacity as needed, and even convert existing fixed-provisioned volumes to thin, reclaiming
unused space back to the pool
. This helps avoid over-allocation of storage in cluster scenarios.
Storage Replica (for disaster recovery) gets performance boosts: it now supports compression of
replication traffic to reduce bandwidth use
, and an  Enhanced Log mechanism that bypasses
some file system overhead, improving block replication throughput and latency
. 
Server Message Block (SMB) Updates: The SMB file-sharing protocol in Windows Server 2025
includes support for the efficient  LZ4 compression algorithm, in addition to existing algorithms
(LZ77, Huffman, etc.)
. Compressed SMB can improve file transfer speeds on slower networks by
sending less data. More notably, Server 2025 includes SMB over QUIC (an SMB transport over UDP/
443 with encryption) for secure, VPN-less access to file shares over the Internet
. When enabled,
SMB over QUIC allows mobile or remote clients to securely connect to an on-prem file server using
TLS 1.3 encryption, with firewall-friendly UDP ports – essentially bringing Azure Files-like connectivity

Security Features and Hardening
Windows  Server 2025  is  a  “security-first” release  with  multiple  layers  of hardening,  building on the
Secured-core initiative (combining TPM, Secure Boot, VBS, etc.) and introducing new protections: 
Credential Guard by Default: Microsoft’s Credential Guard (which uses virtualization-based isolation
to protect LSASS secrets) is now enabled by default on capable systems
. This means on
hardware  that  meets  requirements  (typically  UEFI,  TPM  2.0,  and  supporting  CPU  virtualization
features), Windows Server 2025 will automatically isolate credentials to mitigate theft of hashes/
tickets by malware. On the X9QRi-F+, however, this may not activate since the board does not
support TPM 2.0 (discussed later) and the older CPUs might lack certain virtualization extensions for
virtualization-based security. 
Boot and Firmware Protection: Windows Server continues to support Secure Boot to ensure the
OS boots only trusted, signed bootloaders. The X9QRi-F+ features a UEFI 2.3.1 firmware with Secure
Boot capability
, so when running Server 2025 it is recommended to enable Secure Boot in the
BIOS to guard against bootkits and unauthorized Option ROMs. Additionally, the server supports
UEFI  firmware (ACPI  4.0,  SMBIOS  2.7),  which  aligns  with  modern  Windows  requirements
.
(Legacy BIOS boot is also supported on this board, but using UEFI is preferable for Windows Server
2025 to leverage modern security features.) 
Virtualization-Based  Security  (VBS)  Enclaves: A  new  feature  called  VBS  enclaves  allows
applications to run sensitive code in secure enclaves isolated by the hypervisor
. In essence, even
if an admin or kernel is compromised, the enclave’s data remains protected. This is similar in spirit to
technologies like Intel SGX or AMD SEV, but implemented via Windows hypervisor. Use of VBS
enclaves may require specific CPU support (e.g. Mode Based Execution Control (MBEC) or other
second-level translation features). The Intel Xeon E5-4600 v2 CPUs (Ivy Bridge architecture) do
support  VT-x  and  EPT,  but  lack  newer  features  like  MBEC  and  have  no  SGX;  thus,  while  core
virtualization will work, certain VBS functionalities might not be available or might run with reduced
security on this platform. 
Active  Directory  Security  Improvements: If  the  X9QRi-F+  server  will  function  as  a  domain
controller, note that Active Directory in Windows Server 2025 gets some notable updates. There is an
optional 32K directory database page size (vs. 8K legacy) which greatly raises various AD object
limits (for example, allowing ~3,200 values in multivalued attributes vs ~1,200 before)
. This
can improve AD scalability in large enterprises. There are also improvements to AD object recovery
and  confidential  attribute handling,  and  the  introduction  of  Delegated  Managed  Service
Accounts (dMSA) which eliminate manual password management for service accounts by having AD
manage  them  automatically
.  These  are  advanced  AD  features  that  enhance  security  and
manageability in enterprise scenarios. 
Other Security Features: Windows Server 2025 integrates Windows Defender Advanced Threat
Protection and other ATP capabilities for malware detection and endpoint security (cloud-delivered)
. It also includes LAPS (Local Administrator Password Solution) built-in, which automatically

Remote Management and Hybrid Integration
Managing Windows Server 2025 is made easier both locally and especially in hybrid cloud scenarios, which
is valuable for a system like the X9QRi-F+ that might be deployed on-premises but managed remotely: 
Windows Admin Center & Azure Arc: Windows Server 2025 has deep integration with Azure Arc for
hybrid management. A new “Azure Arc Setup” wizard comes pre-installed (as a Feature on Demand) to
onboard the server to Azure Arc easily
. Once connected, you can use Windows Admin Center
(WAC) in the Azure portal to manage the server’s roles, features, and settings through a web GUI
. This essentially brings the familiar WAC interface into Azure, providing a single pane for
managing on-prem and cloud servers together
. For an X9QRi-F+ host, this means you can
perform remote management (e.g., view performance, configure features, manage VMs, etc.) from
anywhere via Azure’s secure portal, even if the server itself is behind a firewall, as long as it’s Arc-
connected. 
Azure Hybrid Services: With Arc integration, Server 2025 also offers pay-as-you-go licensing and
other  cloud-based  benefits
.  While  licensing  is  beyond  our  scope,  the  key  point  is  that
connectivity to Azure enables features like Azure Site Recovery (for VM replication to cloud)
,
cloud-based  monitoring and best-practice assessments (Arc can scan the server and suggest
configuration improvements)
, and even just-in-time remote support where Microsoft support
personnel can, with permission, get time-limited access to assist with issues
. These capabilities
can extend the lifecycle and support of older hardware like the X9QRi-F+ by integrating it with
modern cloud management frameworks. 
PowerShell  and  Automation: Windows  Server  2025  includes  PowerShell  7 (the  latest  cross-
platform, modern PowerShell) for improved scripting and automation
. This allows admins to use
advanced  modules  and  scripts  to  manage  the  server  both  locally  and  remotely.  Remote
administration via PowerShell Remoting (over WinRM/SSH) is fully supported, and the inclusion of
OpenSSH server by default (a feature carried over from Server 2019/2022) means you can securely
SSH into the server for management tasks
. 
Built-in Remote Management Tools: The OS still supports traditional tools like Remote Desktop,
Server Manager, and the new Windows Admin Center (which can also be installed locally if not using
Azure Arc). In Windows Server 2025’s desktop experience (GUI mode), the environment is similar to
Windows 11’s interface
, and tools like the modern  Windows Terminal and  WinGet package
manager  are  available  by  default  for  administrator  convenience
.  This  makes  local  and
remote management more streamlined. 
Out-of-band Management (Hardware): Separately from the OS, it is worth noting the Supermicro
X9QRi-F+ includes a dedicated Baseboard Management Controller (BMC) with IPMI 2.0 + KVM-over-
LAN support
.  This  allows  hardware-level  remote  management  –  you  can  power  cycle  the
machine, access BIOS, and use a remote console independent of the OS. When planning remote

Performance Characteristics of Windows Server 2025
Windows Server 2025 is designed to deliver robust performance on modern hardware, and it introduces
several under-the-hood improvements in memory management, CPU scheduling, I/O throughput, and
networking. When running on the Supermicro X9QRi-F+ platform (which is an older but high-end 4-socket
server board), these OS enhancements will generally improve efficiency, though the extent will be bounded
by the hardware’s capabilities (DDR3 memory, older Xeon cores, limited SATA bandwidth, etc.). Below is an
analysis of the OS performance characteristics in key areas: 
Memory Management and Scalability
The  memory  subsystem  in  Windows  Server  2025  can  scale  to  extremely  large  RAM  sizes  (up  to  4
petabytes), ensuring that even memory-intensive workloads are handled with ease
. The OS includes
refined algorithms for memory allocation, NUMA awareness, and caching. In a multi-socket system like the
X9QRi-F+ (which has a NUMA node per CPU socket), Windows will automatically distribute and balance
memory allocations per NUMA node to optimize local memory access. The OS’s support for disaggregated
memory and huge memory pages has been improved, which can help in HPC or virtualization scenarios
by  reducing  overhead.  For  example,  Hyper-V  on  Server  2025  can  employ  large  memory  pages  more
aggressively, and features like Dynamic Memory (if using Hyper-V) are expected to work more efficiently
for guest VMs, adjusting allocations with less fragmentation. 
On  the  Supermicro  X9QRi-F+,  the  maximum  memory  is  1   TB  (with  32  DDR3  RDIMMs)
.  While
DDR3-1600/1866 memory has lower bandwidth than newer DDR4/DDR5, Windows Server 2025’s memory
manager  will  utilize  all  available  memory  for  caching  disk  operations  and  handling  large  in-memory
workloads as needed. The OS’s ability to handle memory pressure is enhanced by tools like DTrace, which is
now built-in and can help profile memory and CPU usage in real time
. Administrators can use such tools
to  fine-tune  performance  (for  example,  observing  if  the  system  is  swapping  or  experiencing  NUMA
imbalances). In summary, Windows Server 2025 will fully utilize the X9QRi-F+’s memory capacity, and its
improvements in scalability mean the OS itself won’t be a bottleneck even as the hardware approaches its
limits. 
CPU Utilization and Scheduling
Windows Server 2025 introduces an optimized CPU scheduler and smarter resource allocation, which is
particularly beneficial for systems with many cores or multiple CPUs. The OS can handle up to 2048 logical
processors, as noted, and while the X9QRi-F+ (with 4 × Xeon E5-4600 v2 CPUs) will present at most 48
physical cores / 96 logical threads, the scheduler improvements still help in this context. For example, the
OS uses CPU groups to manage large core counts; in our case it won’t need to split into groups, but it will
leverage all cores for parallel tasks. 
The scheduler also includes security-aware features (e.g., retpoline and hardware mitigations for Spectre/
Meltdown are built-in), which do incur some overhead on older CPUs. The Xeon E5-v2 series does support
speculative execution mitigations via microcode/OS, and Server 2025 will enable those by default to ensure

Storage I/O and Disk Performance
As noted, Windows Server 2025 brings significant storage performance gains, especially for fast disks. The
NVMe optimization is a key improvement – the OS can achieve up to 60% more IOPS on the same NVMe
SSD hardware compared to Server 2022
. This is partly due to a more efficient Storport driver and
mitigations for interrupt handling overhead. On the X9QRi-F+, if you use SATA SSDs or HDDs on the onboard
Intel C602 SATA controller, the performance will mostly be limited by the 6Gb/s SATA3 interface. However,
the OS will still take advantage of NCQ (native command queuing) and other storage stack improvements. 
If high performance storage is needed, one could install a PCIe NVMe drive or an HBA/RAID card. Windows
Server 2025 has in-box drivers for many common storage adapters and will benefit from the NVMe and
RAID enhancements automatically. For example, a PCIe 3.0 NVMe on this board (though running at PCIe 3.0
x4 speeds) could see better I/O due to lower latency in the OS stack. Features like  multi-queue I/O
scheduling, which were introduced in Server 2016 and refined since, are at their best in Server 2025 –
meaning the OS can efficiently handle many simultaneous disk operations by leveraging multiple processor
cores for I/O. 
The ReFS block cloning feature mentioned earlier also has performance implications: copying or cloning
large files (such as VHD/VHDX virtual disks for VMs) is far faster and uses much less disk bandwidth now
.  This  can  drastically  shorten  maintenance  tasks  like  backing  up  VMs  or  duplicating  datasets.
Additionally, if deduplication is enabled (now possible on ReFS in 2025), read I/O for duplicate data is
reduced and more of the working set might be served from cache, effectively boosting read performance
for redundant data scenarios. 
One thing to consider is that the X9QRi-F+ chipset (C602/X79 platform) is an older generation chipset – it
supports SATA2/3 and some legacy PCIe 3.0 lanes. The Windows 2025 storage stack is fully backward-
compatible with such hardware, but some new storage features (like Storage Spaces Direct with NVMe

Network Throughput and Stack Efficiency
Windows Server 2025 includes a range of  network performance enhancements, which can especially
shine with modern high-speed network adapters. The OS has improved the TCP/IP stack – for instance, it
has better default TCP congestion control and recovery (building on innovations like TCP HyStart++ and
RACK loss recovery that were introduced in Windows 11/Server 2022). It also adds support for ultra-high-
speed networks such as 25 GbE and 50 GbE, with tuned defaults to reduce CPU overhead at those speeds
. Networking features like  Receive Segment Coalescing (RSC) and  Virtual Receive Side Scaling
(vRSS) for VM workloads are all present and optimized. 
On the Supermicro X9QRi-F+, the onboard NICs are dual Intel i350 Gigabit Ethernet ports
. These are
capable and reliable NICs, but limited to 1 Gbps throughput per port. They do support some offloads
(checksum offload, LSO, VMDq for virtualization), but they do not support SR-IOV or RDMA. This means
advanced features like AccelNet (which automates SR-IOV for VMs) won’t apply on the stock NICs – you
would need to add, say, a 10GbE or 25GbE NIC that supports SR-IOV if you wanted to utilize that feature on
this server. If a modern NIC is added via PCIe (the board has several PCIe 3.0 x8/x16 slots), Windows Server
2025 will take advantage of it fully: for example, a 10GbE Intel X540 or X550 NIC could be used, and though
the CPU is older, the OS would handle the higher interrupt rate by possibly utilizing features like Receive
Side Scaling (RSS) across multiple cores to distribute network load. 
Even with the 1GbE interfaces, the OS improvements are beneficial. The networking stack in Server 2025
has been hardened and made more efficient. For instance, default network security policies (if managed via
WAC) block unwanted inbound traffic by default
, which can slightly reduce exposure and load. The
inclusion of SMB compression (LZ4) means that copying large files over the network (if both ends are 2025)
could be faster on bandwidth-constrained links – although on a 1 Gbps LAN, the benefit may be limited by
CPU compression speed (the Xeon E5 v2 does have AES-NI and is reasonably powerful per core, so LZ4 at 1
Gbps should be fine). 
Another improvement is Network ATC for cluster networks (making it easier to configure QoS and VLANs
for different traffic types)
. In a single-server scenario this is less relevant, but if the X9QRi-F+ is part of a
failover cluster, Network ATC can ensure that say storage replication traffic vs VM traffic are separated and
optimized with minimal admin effort. 
Overall, Windows Server 2025’s network stack is highly optimized: lower latency, better multi-core scalability
for packet processing, and enhanced security. On an older platform, you might not be able to exploit the
highest-end capabilities (like 50GbE NIC offloads or RDMA), but you will still get a rock-solid networking
foundation that is more efficient than previous Windows Server versions. Expect that the dual Intel i350
NICs will be able to run at near line-rate 1 Gbps with low CPU usage (~5-10% of one core typically, thanks to
offloads), and if you team/bond them or use both, the OS can utilize both ports (e.g., with SMB Multichannel
for 2 Gbps aggregate SMB throughput). If needed, upgrading to a faster NIC is straightforward and
supported by the OS with improved performance at those higher throughputs
.

Compatibility and Installation on Supermicro X9QRi-F+
The Supermicro X9QRi-F+ is a quad-socket server motherboard (approx. circa 2013) that supports Intel Xeon
E5-4600 and E5-4600 v2 series processors (up to 12 cores per CPU) and uses the Intel C602 chipset
.
Installing Windows Server 2025 on this board is technically feasible and generally runs well, but there are a
few compatibility and setup considerations to ensure a smooth experience. This section covers chipset/CPU
support, BIOS requirements, driver availability, and other installation notes specific to this platform. 
Chipset and CPU Support
CPU Architecture: The X9QRi-F+ supports the Intel Xeon E5-4600 v2 family (“Ivy Bridge-EP”, 22nm)
and v1 (“Sandy Bridge-EP”) in LGA2011 sockets
. These CPUs are 64-bit, support the required
instruction extensions (Intel 64, NX bit, VT-x, VT-d, etc.), and in principle can run Windows Server
2025. However, it’s important to note that these older Xeon E5 processors are not on Microsoft’s
official supported CPU list for Windows Server 2025. Microsoft’s certified processor list for Server
2025 starts at much newer generations (e.g. Intel Scalable Xeons Gen2+ and AMD EPYC 7xx2+);
pre-2015 CPUs like the Xeon E5-v2 are not included
. This does not mean it won’t work – it
simply  means  Microsoft  won’t  test  or  guarantee  Windows  2025  on  such  old  silicon  for  new
deployments. In practice, many admins have reported success running Server 2022 and even 2025
on Xeon E5-v2 systems. The Reddit community, for example, found that a dual Xeon E5-2690 v2
system could run Windows Server 2025 (used as a desktop OS to bypass Windows 11’s restrictions)
without major issues
. So compatibility is generally fine, but be aware you are in “unsupported”
territory. 
Performance and Features: Because the Xeon E5-4600 v2 lacks some modern CPU features, a few
Windows 2025 capabilities will be limited. For instance, as discussed,  Credential Guard and VBS
might not enable due to missing second-level address translation features like MBEC. The processors
do have first-generation Intel VT-x with EPT and VT-d for virtualization, which  are sufficient for
running Hyper-V and basic VBS isolation. They also have AES-NI for encryption, so features like
BitLocker and SMB encryption will use hardware acceleration. Overall, the OS will utilize the CPUs
fully, but just note that the raw performance is that of 2013-era 2.0–2.9GHz cores with no turbo
beyond 3.x GHz and no AVX2 instructions. Modern workloads (especially ones using heavy AVX2/
AVX-512 on newer CPUs) will run, but slower. That said, standard server tasks (AD DS, DNS, file
services, moderate virtualization) should run comfortably within the CPU capacity. 
Chipset (Intel C602): The C602 server chipset on the X9 provides the SATA ports, USB, PCIe lanes,
etc. Windows Server 2025 includes in-box support for the Intel C600 series chipset. Basic devices like
the PCIe root ports, USB 2.0 controllers, and SATA AHCI controller will be recognized with Microsoft’s
standard drivers. If the SATA controller is set to AHCI mode, the install should see any connected
drives natively. If it’s in Intel RSTe RAID mode and you have a RAID volume defined, you might need
to load the Intel RSTe driver at install (Windows 2025 may not include the out-of-the-box driver for
this older RAID controller). Intel last provided drivers for RSTe (Rapid Storage Tech Enterprise) for
Windows Server 2016/2019, but those drivers often still work on 2022/2025. Alternatively, using AHCI
mode is simplest unless you require a firmware RAID. 
Memory and NUMA: No compatibility issues here – the OS will see the memory installed. With four
CPUs, the system presents a NUMA topology that Windows will recognize and optimize for. One

BIOS/UEFI and Firmware Considerations
BIOS Version: It is  highly recommended to update the X9QRi-F+ to the latest BIOS firmware
before installing Windows Server 2025. Supermicro released BIOS updates for this board up through
mid-2015 (to support the v2 processors and fix bugs). The latest revision (often version 3.x or similar)
should include the latest CPU microcodes and stability fixes. Updated microcode is important for
security (Spectre/Meltdown mitigations) and stability under heavy loads. Administrators have noted
that BIOS updates are a first step to resolve any weird issues on Supermicro platforms
. For
example, if you encounter instability or crashes, ensure the BIOS is current and loaded with optimal
defaults. 
UEFI vs Legacy Boot: The X9QRi-F+ features a UEFI BIOS (conforming to UEFI 2.3.1 and supporting
ACPI 4.0)
. Windows Server 2025 can install in either UEFI or Legacy (CSM) mode. UEFI mode is
strongly recommended for a few reasons: it allows use of GPT partitioned boot drives (needed if
your boot volume is over 2 TB), and it enables Secure Boot. If you install in legacy BIOS mode, you
won’t be able to enable Secure Boot and might run into the MBR 2 TB boot disk limit. In the BIOS
setup, ensure the boot mode is set to UEFI. You can also enable Secure Boot (load the default keys
provided by Supermicro) to take advantage of OS boot chain verification
. Secure Boot on this
board should work since it’s listed as supported, guarding against boot-time malware by verifying
signatures of the boot loader
. 
TPM (Trusted Platform Module): A notable compatibility point is the lack of TPM 2.0 support on this
motherboard. The X9 generation boards pre-date TPM 2.0; Supermicro did offer optional TPM
modules (via header) for some X9 boards, but they were TPM 1.2 modules. In fact, users have
reported that “TPM 2.0 module for this motherboard doesn’t exist… [you] would need a Supermicro X10 or
higher” to have TPM 2.0
. This means if you require TPM 2.0 for features like BitLocker with TPM
unlocking, VBS with Credential Guard, or generally to satisfy modern OS recommendations, you’re
out of luck. Windows Server 2025 does not actually require a TPM to install or run (unlike Windows
11 which mandates TPM 2.0 for official support), so the OS will still function on the X9QRi-F+ without
one. But certain security features will fall back or be disabled. For example, without TPM 2.0,
Credential Guard cannot store its secrets in hardware, and the system cannot be a “secured-core
server” by Microsoft’s definition. If security is a priority, you might consider using an older TPM 1.2
module if available (it could at least be used for BitLocker encryption, albeit without the enhanced
algorithms of TPM 2.0).

Hyper-V and Virtualization on the X9QRi-F+
Deploying Hyper-V or other virtualization solutions on the Supermicro X9QRi-F+ (Xeon E5-v2 platform)
under Windows Server 2025 is quite feasible and can be effective for many workloads, but it comes with
some caveats due to the age of the hardware. Here are key points and “notes from the field” regarding
virtualization on this setup: 
Hyper-V Role Compatibility: Windows Server 2025 Hyper-V requires a 64-bit processor with Second
Level Address Translation (SLAT). The Xeon E5-4600 v2 does support SLAT (Intel EPT), and Intel VT-x
virtualization extensions, so it meets the technical requirements to run Hyper-V and host VMs. You’ll
need to enable “Intel Virtualization Technology” (VT-x) and “VT-d” in the BIOS if they aren’t already on
(on Supermicro boards they are usually enabled by default, but double-check BIOS settings for
“Virtualization” and “VT-d”). With those on, the Hyper-V role should install without issue and you can
create VMs that utilize the full CPU and memory of the machine. 
Performance for VMs: Each Xeon E5-46xx v2 CPU has up to 12 cores (24 threads). In a fully loaded
configuration (4 CPUs, 12C each, HT on) you have 48 physical cores / 96 logical processors available
to Hyper-V. Windows Server 2025 Hyper-V can handle this easily (far below its 2048 LP limit
). The
scheduler will distribute VMs across the NUMA nodes. By default, Hyper-V will treat each socket as a
NUMA node with its local memory, and it will try to keep a VM’s memory allocation within one node
for performance (as long as the VM’s vCPU count doesn’t exceed the cores of a single socket, it will
stay “NUMA local”). You can manually configure NUMA spanning settings if needed, but the defaults
are fine.

(AccelNet) feature in Windows Server 2025, which streamlines SR-IOV configuration

this hardware unless a SR-IOV capable NIC is added. If high network throughput or low latency for
VMs is a goal, installing a PCIe 10GbE or 40GbE NIC that supports SR-IOV (e.g., Intel X710 or
Mellanox ConnectX-4) would allow you to take advantage of those Hyper-V capabilities on this OS.
Otherwise, expect roughly up to ~3-4 Gbps total throughput through a Hyper-V virtual switch on a 1
Gbps NIC (since multiple VMs have to share 1 G link, the limit is 1 Gbps per NIC).

Known Issues and Limitations
When running Windows Server 2025 on the X9QRi-F+ platform, a few known issues or limitations should
be noted: 
Lack of Official Support: As mentioned, Intel Xeon E5-v2 series CPUs are not officially supported in
Server 2025. This means if you run into an OS bug, Microsoft support might not assist you unless
you reproduce it on supported hardware. While the community and our testing indicate it works,
you’re essentially in an unsupported configuration. This is more of a theoretical limitation – day-to-
day it likely won’t matter, but it’s worth acknowledging. 
No TPM 2.0: The X9QRi-F+ cannot accomodate a TPM 2.0 module
. This limits certain security
scenarios.  For  instance,  if  you  wanted  to  implement  BitLocker  Drive  Encryption with  a  TPM

like Device Health Attestation or Credential Guard’s highest mode require TPM 2.0. The practical
impact is that the server might not meet some compliance standards that require TPM-based
attestation. If this is a lab or non-critical deployment, it may not matter. If it’s going into production
in an environment with strict security requirements, this could be a show-stopper for using this older
board. 
Older BIOS and UEFI Limitations: The motherboard’s UEFI, while functional, is not as advanced as
modern ones. Beyond the NVMe boot issue discussed, it may also lack some quality-of-life features.

Deployment Services with UEFI HTTP boot, that won’t work on this hardware. 
Power  Consumption  and  Heat: While  not  an  OS  issue,  running  this  board  fully  loaded  with
Windows Server 2025 means you’ll be drawing significant power even at idle compared to newer
hardware. The OS itself might try to idle cores, but the power gating on older Xeons is not as

it’s usually disabled on multi-socket Supermicros, but good to confirm. 
Power/Performance: Set the BIOS power management to “Performance” or OS Controlled (and
then in Windows set High Performance plan). On some X9 boards, there is a “Power Efficient” vs
“Performance” setting. The latter will minimize CPU C-state stepping and give more consistent
performance (at the cost of power). If you prefer the CPUs throttle when idle, you can choose
Balanced, but for a server workload performance mode is often recommended. 
Hyper-Threading: Ensure Hyper-Threading is Enabled (unless you have a specific reason to disable
it, such as certain licensing or security considerations). Hyper-Threading will give you up to ~20-30%
throughput boost for many workloads. There were past concerns about side-channel attacks on HT
(like L1TF vulnerability), but those can be mitigated via patches rather than disabling HT in most
cases. 
Boot Mode & Secure Boot: Set Boot Mode = UEFI. Enable Secure Boot and load the default keys (as
long as you intend to run Windows or other signed OS). This will help protect the boot process
. If
you run into any boot issues after enabling Secure Boot (for example, if using some unsigned kernel
drivers or utilities in pre-boot), you might need to add keys or disable it, but generally Windows
Server works with Secure Boot on. 
Above 4G Decoding: If you plan to install devices that use large BAR memory ranges (like a GPU or
certain NVMe RAID cards), check if the BIOS has an option for “Above 4G Decoding” or “64-bit PCI
decoding” and enable it. This allows the BIOS/OS to map MMIO space above 4GB address range,
which is needed if you have devices that collectively require more than 4GB of address space
(common if a large GPU with 16GB VRAM is installed). This setting is often found in later-gen boards;
some X9 BIOS have it hidden or not available. If it’s present, enabling it preemptively can avoid
issues with devices not showing up in Windows due to address space collisions. 
Install Latest Drivers (if available): After OS install, check Device Manager. If any devices are
unnamed (e.g., “Base System Device”), install the Supermicro or Intel chipset INF to properly tag
them. For NICs, consider installing the Intel PROSet drivers for Windows Server (even if 2025 isn’t
listed, the latest available for 2019/2022 should work). This can sometimes provide adapter teaming
software or advanced diagnostics. For storage, if using RAID, install the appropriate Intel/LSI drivers
and management utility (like Intel RST CLI or MegaRAID Storage Manager) to monitor array health.
While Microsoft’s in-box drivers are stable, vendor drivers can offer performance tuning or full
feature support.

Verify  Event  Logs  and  Device  Manager: Keep  an  eye  on  the  Windows  Event  Viewer  for  any
warnings or errors that might indicate a driver or hardware issue (for example, storport timeouts,
corrected ECC errors, etc.). Also verify that all 4 CPUs and full memory are recognized by the OS (you
can check System Information or Task Manager > Performance). If something looks off (like only 3
CPUs showing), that could indicate a CPU or socket not initialized – re-seat CPUs or adjust BIOS
settings accordingly. 
Stress Test the System: After installation and setup, it’s wise to run some stress tests to ensure
stability under load. For example, run Hyper-V with some test VMs doing CPU+memory stress, or use
tools  like  Prime95,  memtest,  or  disk  benchmarking  (CrystalDiskMark  on  your  drives,  iperf  for
network). This can reveal any cooling insufficiencies or configuration issues (like a mis-seated RAM
module causing correctable ECC errors under load, etc.). It’s better to identify and address such
issues early. 
Plan for Redundancy: This is more operational advice – if this server will host important workloads,
remember that the hardware is old and components (PSUs, drives, fans) can fail. Ensure you have
proper cooling (all fans operational – this board has 10 fan headers and expects a robust chassis
cooling
). Consider keeping a cold spare or at least have a backup strategy for the VMs/data.
Windows Server 2025 can use Storage Replica to copy data to another server or Azure for backups.
Utilize those OS features to mitigate the risk of hardware failure. 
Leverage New OS Features Wisely: Make use of the OS enhancements to get the most out of the
hardware. For example, if running VMs, use VM Start Order Priority and Automatic Start Delays
to stagger VM boot if you have many (to avoid power spike and disk thrash on boot). Use Storage
QoS if multiple VMs share a disk system, to prevent one VM from saturating the I/O. If this server is
an all-in-one, use Nested Virtualization if you want to run Hyper-V inside a VM (yes, Server 2025
supports nesting even on older Intel CPUs that have VT-x/EPT – useful for lab scenarios). Also, enable
Windows Admin Center for a modern management experience – you can install it on Windows
Server 2025 (it’s a separate download or use via Azure Arc as mentioned). WAC gives a nice GUI to
monitor performance, manage updates, etc., which is helpful if you don’t want to RDP into the server
regularly. 
Security Updates: Continue to apply Windows Updates. Even though the hardware is old, the OS
updates  (especially  security  patches)  are  crucial.  Windows  Server  2025  will  be  supported  with
updates into 2029 (mainstream) and 2034 (extended)
. Staying patched will keep the server
secure and stable. If any update ever seems to cause an issue (rare, but e.g. some early 2025 update
reportedly caused DC connectivity issues
), you can always roll it back, but generally, trust the
update process. 
By following the above recommendations, you can achieve a stable and well-performing system. Many IT
professionals have successfully modernized older servers like the X9QRi-F+ by running the latest software
on them – the key is to mind the details (firmware, configuration, realistic expectations). In conclusion,
Windows Server 2025 can breathe new life into the Supermicro X9QRi-F+ platform, providing access to
current-generation features and security on this veteran hardware, as long as one carefully addresses the
compatibility and optimization points discussed.
