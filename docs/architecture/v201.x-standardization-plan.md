# v201.x Standardization Plan

**Project:** Monkey-Head-Project  
**Preparation date:** 2026-07-17  
**Status:** Draft preparation for Dylan L.R. Pollock's human oversight  
**Repository predecessor:** `master-plan-v120.3.json` and README v120.3  
**Website predecessor:** DLRP.ca v200.x structural and presentation discipline  

> [!IMPORTANT]
> This document does not independently lock canon. It prepares a reviewable merge between the v120.x repository architecture and the v200.x website framework. v201.x becomes accepted only through Dylan's explicit approval or intentional merge of a designated canonical update.

## 1. Purpose

v201.x is intended to become the first standardized project layer in which:

- repository-facing architecture;
- public website narrative;
- machine-facing planning;
- implementation evidence;
- physical embodiment direction;
- asset and release discipline;
- and human oversight

use compatible terminology without being flattened into one false source of truth.

The goal is not to import the website into the repository or to rewrite the repository around presentation. The goal is to define one standard that tells each layer what it owns, how it cites other layers, and how disagreements are surfaced for review.

## 2. What v120.x contributes

The v120.x repository line remains the accepted predecessor for:

- explicit truth layers;
- Dylan-only canon authority;
- PyHuey as the primary GUI and core-runtime direction;
- current `huey` namespace and target `hueyos` namespace;

## 3. What v200.x contributes

These are framework and presentation standards. They do not override repository architecture or implementation evidence.

## 4. v201.x standard model

v201.x should standardize five coordinated layers.

| Layer | Owner | Primary artifact | Rule |
|---|---|---|---|
| **Canon and architecture** | Human oversight | accepted master plan and decision records | Defines accepted direction and unresolved questions |
| **Repository front door** | Repository documentation | `README.md` | Explains accepted architecture without claiming unimplemented behavior |
| **Runtime and implementation** | Code, tests, hardware evidence | source tree, logs, fixtures, hardware records | Proves what actually exists or runs |
| **Public coherence** | DLRP.ca | static website and release records | Presents the project clearly while citing source status |
| **Lineage and continuity** | Archives and predecessor files | v120.x, v200.x, transcripts, reports | Preserves history without silently becoming current canon |

## 5. Architecture alignment to review

The v201.x candidate should present the following as reviewable direction rather than automatic canon:

- Huey is one embodied AI node.
- Monkey-Head-Project is the umbrella and eventual collective around one or more valid nodes.
- Brain and Body remain useful node-local functional domains.
- Farm is optional shared or supra-node infrastructure rather than a constitutive part of every Huey.
- One valid node comes before operational collective claims.
- Huey V4 is the active physical-cohesion direction.
- The existing i9/TUF/Optane system is intended to become the V4 kernel after validation.
- Four node-local GPUs are a working direction.
- `3 × Tesla V100 32 GB + 1 utility GPU` remains provisional until acquired, fitted, powered, cooled, and measured.
- CPU-first transcription, orchestration, logging, I/O, and support duties remain practical first assignments.
- Unified multi-GPU inference is a target compute posture, not an implemented fact.
- Exact and augmented bifurcation remain future lineage concepts above node validity.
