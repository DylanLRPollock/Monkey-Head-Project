## 6. v200.x framework items proposed for standardization

The following should become v201.x project standards rather than remaining website-only habits:

- explicit source origin and synchronization state;
- truth-layer labels on architecture and hardware claims;
- compact release manifests and checksums;
- generated-file inventories;
- asset provenance and image-role records;
- static/offline-capable public release packaging;
- no remote font dependency;
- no private material in public packages;
- deliberate image use with alt text, intrinsic dimensions, crop policy, and actual route purpose;
- one source registry for routes/navigation/discovery where the website is concerned;
- machine-readable audit records beside human-readable reports;
- fresh-extraction validation before release declaration.

## 7. Items that must remain separate

Do not merge these into one document or authority:

- website narrative and machine-facing master plan;
- accepted direction and runtime reality;
- repository README and public homepage copy;
- private continuity profile and public biography;
- target-state governance and implemented authority;
- node-local compute and Farm/collective infrastructure;
- Huey, Atlas, Dylan, LabTech, and external services;
- historical bifurcation language and accepted current architecture;
- generated release artifacts and hand-maintained source documents.
